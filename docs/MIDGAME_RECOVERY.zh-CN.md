# 雀魂中途启动：实现与手动验收

本地修复基于 Akagi 0.1.2，在 `codex/fix-majsoul-browser-crash` 分支维护。适用于现有 Chromium CDP 捕获环境和受支持的雀魂官方 HTTPS 页面。恢复不会开启自动操作；验收时保持该开关关闭。

**用户对照反馈：原版 0.1.2 在“雀魂先开”和“Akagi 先开”两种顺序下各一次均崩溃；仅关闭自动恢复探针的版本在两种顺序下各一次均正常并进入对局。用户同意以这些结果通过因果关卡。** 浏览器版本和是否观察满 60 秒未补充，不能把此反馈写成更完整的验收记录，也不能据此确定浏览器内核中的具体故障函数。

当前修复移除 WebSocket 堆扫描、消息监听器注入和主动关闭连接。仅在用户点击「恢复并继续」时刷新唯一绑定的官方页面一次。最终修复版仍需单独进行下述人工验收，诊断版正常不等于最终版已通过。

## 使用步骤

1. 在免费的 AI／测试房间开局，暂时不要启动捕获。建议使用较长的行动时间。附加模式需要浏览器原本已提供调试端口；恢复按钮不能把普通未开启调试的浏览器转为 CDP 模式。
2. 使用本分支构建的 Akagi，保持原有浏览器附加配置；只保留一个受支持的官方游戏标签页。确认内置机器人已启用，关闭自动操作，再启动捕获。Edge 如显示本次调试连接请求，按浏览器提示允许。附加页面和创建 WebSocket 本身不得刷新页面或关闭连接。
3. 在捕获面板点击一次「恢复并继续」。即使还没收到游戏动作、面板显示「未接入对局」，只要官方页面已唯一绑定，按钮也可以出现。
4. 等待恢复状态。程序作废旧建议和操作窗口、清空画布缓存，对同一页面发出一次刷新请求，再由客户端自行加载、认证与同步。刷新 CDP 调用最多等待 3 秒；成功后等待恢复屏障最多 60 秒。失败或超时不补发第二次刷新，只有用户再次主动点击才是新尝试。
5. 出现「局面已恢复」后，核对座位、人数、手牌、副露、牌河、立直及宝牌。**恢复屏障完成前不得出现历史建议或自动点击。** 屏障完成后，如果同步快照的最后一个动作确实包含本玩家的待行动操作列表，且重建后的引擎确认可以行动，程序立即推理一次并显示「恢复建议 · 请手动操作」。不会逐条推理历史动作，也不会将建议动作喂回模型。
6. 恢复窗口的建议只供手动操作：`passed_waiting_time` 的单位与含义尚未得到实机验证，因此不恢复该窗口的自动输入许可或剩余时间预算。即使自动操作开关已经打开，或显示建议后再打开，也不能执行这条恢复建议。缺少待行动操作、不是本玩家窗口、局面已变化或模型无法生成建议时不猜测；手动完成当前行动，随后观察下一有效实时窗口是否正常给出建议。后续新实时窗口仍使用原有决策和自动操作逻辑；本次人工验收保持自动操作关闭。
7. 三麻、四麻分别核对恢复后的真实局面及至少三个新操作窗口的建议。另对两种启动顺序各连续验证五次，页面加载后观察至少 60 秒，确认实际已绑定官方页面且无对应新增浏览器崩溃报告。未执行的项目必须标注「未验收」。

退出旧 Akagi 实例并保留游戏浏览器，再运行已构建的 `target/debug/akagi`。若需要显式指定现有配置：

```sh
./target/debug/akagi --config /你的现有配置路径/config.toml
```

自行重新构建时使用：

```sh
cd frontend
npm run build
cd ..
cargo build --features custom-protocol --bin akagi
```

`custom-protocol` 用于嵌入前端资源，运行该构建不需要 Vite 开发服务器。

## 恢复判定与记录

本次日志目录可在 Akagi 界面查看。保留整个本次日志目录，并记下三麻／四麻、接入阶段和人工操作的时间。

| 证据 | 位置与判定 |
|---|---|
| 恢复方式与阶段 | `majsoul/recovery.log`：当前流程只产生 `method=reload`；旧日志中的 `reconnect` 仍可读取。每条记录带 `ts_ms`、代次、原因、批次事件数与起止序号，可计算各阶段耗时。 |
| 输入保护 | `majsoul/autoplay.log`：恢复期间和开关关闭时不得出现新的自动输入。`reload_failed` 表示刷新调用失败；`reload_restore_timeout` 表示刷新后未完成局面恢复，均保持输入阻断。 |
| 协议与决策时间线 | `inspector.jsonl`：结合脱敏协议方法、事件与机器人响应，核对恢复后实时窗口的顺序。 |
| 当前局记录 | `majsoul/*.mjai.jsonl` 与历史：首次中途接入标注「中途采集」，不参与完整对局的名次及 PT 统计。 |

恢复成功需要真实局面一致、状态消费者完成屏障、后续有效窗口正常产生建议；单纯网页加载成功不能算通过。失败时记录原因；网络不可达与客户端不支持恢复是不同原因，不能仅凭连接超时推断功能永远不可用。

发生非预期导航、关闭页面、切换平台或停止捕获时，当前恢复及旧操作取消。当前尝试的一次预期刷新导航可以继续恢复；失败或取消后清除该许可，之后的人工导航不得继承它。多个官方页面不会选择其中一个刷新。程序不枚举页面内未观察到的 WebSocket，不再以识别唯一连接作为恢复前提，也不会选择或主动关闭任何连接。失败后不会循环刷新；重新尝试需要用户主动触发。

## 已实现的边界

- 使用既有 CDP 网络事件进行被动采集；没有恢复用 `Runtime.queryObjects`、WebSocket 对象注册表或消息监听器注入，不分配客户端 RPC 编号，不注入同步请求。
- 认证座位、人数、完整本局起始动作、动作序号与解码结果先校验，再提交完整恢复批次。Tracker、内置模型及自动操作管理器都完成恢复后才解除阻断。
- 历史回放只重建状态，分析只更新最终局面。全部消费者完成后，只对最终待行动局面产生一条明确标注的手动建议。手动输入、新实时动作或恢复代次变化会使这条建议失效；界面收到新实时动作后清除恢复建议，普通实时建议的行为不变。实时事件按序接续，重叠序号与重复开局去重；丢事件、非法批次或消费者溢出使局面失效。
- 决策绑定产生它的捕获代次和服务端操作窗口，核对服务器提供的操作类型。人工操作、窗口关闭、开关改变或页面改变会使旧结果失效。
- 恢复后清空画布尺寸缓存，继续使用现有 Unity 点击、界面就绪检查及确认机制。Unity 排序、摸牌位置和按钮布局是否适配当前版本，仍需上述实机验收。
- 自动操作管理器关闭输入时也持续接收状态，因此恢复后再开启开关仍有立直、摸牌与副露上下文；关闭开关不会点击。
- 同场重连保留已经采集的完整局，替换当前局的重复部分；旧历史没有 `partial` 字段时按完整记录读取。标准 MJAI JSON 不增加恢复元数据。
- 新诊断记录保存生命周期与确认信息，沿用原有脱敏边界，不保存原始协议载荷或凭据。

## 离线验证

`tests/fixtures/midgame_3p.jsonl` 和 `midgame_4p.jsonl` 来自正常日志，只保留匿名标准 MJAI。差分测试在多个接入点比较持续处理与恢复后处理的局面、模型编码输入、合法动作、决策及候选概率。样本含鸣牌、立直、杠、北拔、换局与结束；现有转换及模型回归另覆盖暗杠、抢杠等规则。

另有原始协议构造回归验证认证／同步突发到达、缺失起始动作、序号缺口和损坏动作不能提交；恢复屏障验证过期代次不能解除阻断。修复回归应覆盖单次刷新、3／60 秒超时边界、取消或旧租约不得刷新／污染新代次、失败后清理预期导航，以及自动附加／新连接不发送恢复探针命令。前端回归应检查恢复按钮状态、四种语言的新错误提示和不完整历史统计。实际执行结果以本次 TESTER 记录为准，不能以历史检查代替。

原有 `examples/midgame_smoke.rs` 会启用自动操作，不属于本次验收范围，不运行它。当前验收仅使用界面及人工操作，不以真实自动打牌验证修复。
