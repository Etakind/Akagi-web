# 雀魂中途启动：实现与手动验收

本功能在 `codex/majsoul-midgame-recovery` 分支实现。适用于现有 Chromium CDP 捕获环境和受支持的雀魂官方 HTTPS 页面。自动操作沿用当前开关。

**用户已确认实机结果：当前客户端无刷新路径 A 失败，刷新一次的路径 B 可行，可恢复决策与自动执行。** 此结论来自用户反馈，不代表其他客户端版本或所有对局阶段均已验证。源码保留“先短暂重连，再最多刷新一次”的现有策略。

## 使用步骤

1. 在免费的 AI／测试房间开局，暂时不要启动捕获。建议使用较长的行动时间。附加模式需要浏览器原本已提供调试端口；恢复按钮不能把普通未开启调试的浏览器转为 CDP 模式。
2. 使用本分支构建的 Akagi，保持原有浏览器附加配置；只保留一个受支持的官方游戏标签页。确认内置机器人已启用，开启自动操作，再启动捕获。Edge 如显示本次调试连接请求，按浏览器提示允许。
3. 在捕获面板点击一次「恢复并继续」。即使还没收到游戏动作、面板显示「未接入对局」，只要官方页面已唯一绑定，按钮也可以出现。
4. 等待恢复状态。程序先观察已有 WebSocket 的协议消息，仅关闭唯一识别出的游戏连接一次，交由客户端自行认证与同步。关闭后等待最多 15 秒；无法完成时刷新同一页面一次，等待加载、认证与同步最多 60 秒。CDP 调用另有短超时。
5. 出现「局面已恢复」后，核对座位、人数、手牌、副露、牌河、立直及宝牌。**恢复中不得出现历史建议或自动点击。**
6. 恢复时遗留的当前操作窗口会跳过：`passed_waiting_time` 的单位与含义尚未得到实机验证。需要时手动完成当前行动，随后观察下一有效实时窗口是否正常给出建议并自动执行。
7. 连续验证至少三个新操作窗口。每次应有当前建议、实际点击、对应客户端请求和服务端确认；自动操作记录显示「成功」，原因是 `server_confirmed`。一张建议卡或客户端自行超时弃牌不算通过。

退出旧 Akagi 实例并保留游戏浏览器，再运行已构建的 `target/debug/akagi`。若需要显式指定现有配置：

```sh
./target/debug/akagi --config /你的现有配置路径/config.toml
```

自行重新构建时使用：

```sh
cd frontend
npm run build
cd ..
cargo build --features custom-protocol --bin akagi
```

`custom-protocol` 用于嵌入前端资源，运行该构建不需要 Vite 开发服务器。

## 路径判定与记录

本次日志目录可在 Akagi 界面查看。保留整个本次日志目录，并记下三麻／四麻、接入阶段和人工操作的时间。

| 证据 | 位置与判定 |
|---|---|
| 恢复方式与阶段 | `majsoul/recovery.log`：`method=reconnect` 表示 A；`method=reload` 表示 B。每条记录带 `ts_ms`、代次、原因、批次事件数与起止序号，可计算各阶段耗时。 |
| 自动执行确认 | `majsoul/autoplay.log`：按操作 `id` 串联准备、延迟、执行、待确认和最终结果。成功必须是 `phase=succeeded` 且 `reason=server_confirmed`。 |
| 协议与决策时间线 | `inspector.jsonl`：结合脱敏协议方法、事件与机器人响应，核对恢复后实时窗口的顺序。 |
| 当前局记录 | `majsoul/*.mjai.jsonl` 与历史：首次中途接入标注「中途采集」，不参与完整对局的名次及 PT 统计。 |

A 的验收要求是页面没有刷新，并且恢复后的连续操作得到服务端确认。A 无法完成但 B 满足同样要求，则该客户端需要刷新一次。两种方式都失败时记录原因；网络不可达与客户端不支持恢复是不同原因，不能仅凭连接超时推断功能永远不可用。

发生导航、关闭页面、切换平台或停止捕获时，当前恢复及旧操作取消。多个官方页面不会选择其中一个操作；多个已识别的游戏连接也不会关闭任何连接或自动刷新。失败后不会循环断线或重复刷新。持续未确认的点击沿用既有暂停机制；重新尝试需要用户主动触发。

## 已实现的边界

- 使用 CDP 查询已有 WebSocket，并观察外层协议方法识别游戏连接；不猜测连接顺序，不分配客户端 RPC 编号，不注入同步请求。
- 认证座位、人数、完整本局起始动作、动作序号与解码结果先校验，再提交完整恢复批次。Tracker、内置模型及自动操作管理器都完成恢复后才解除阻断。
- 历史回放只重建状态，分析只更新最终局面。实时事件按序接续，重叠序号与重复开局去重；丢事件、非法批次或消费者溢出使局面失效。
- 决策绑定产生它的捕获代次和服务端操作窗口，核对服务器提供的操作类型。人工操作、窗口关闭、开关改变或页面改变会使旧结果失效。
- 恢复后清空画布尺寸缓存，继续使用现有 Unity 点击、界面就绪检查及确认机制。Unity 排序、摸牌位置和按钮布局是否适配当前版本，仍需上述实机验收。
- 自动操作管理器关闭输入时也持续接收状态，因此恢复后再开启开关仍有立直、摸牌与副露上下文；关闭开关不会点击。
- 同场重连保留已经采集的完整局，替换当前局的重复部分；旧历史没有 `partial` 字段时按完整记录读取。标准 MJAI JSON 不增加恢复元数据。
- 新诊断记录保存生命周期与确认信息，沿用原有脱敏边界，不保存原始协议载荷或凭据。

## 离线验证

`tests/fixtures/midgame_3p.jsonl` 和 `midgame_4p.jsonl` 来自正常日志，只保留匿名标准 MJAI。差分测试在多个接入点比较持续处理与恢复后处理的局面、模型编码输入、合法动作、决策及候选概率。样本含鸣牌、立直、杠、北拔、换局与结束；现有转换及模型回归另覆盖暗杠、抢杠等规则。

另有原始协议构造回归验证认证／同步突发到达、缺失起始动作、序号缺口和损坏动作不能提交；恢复屏障验证过期代次不能解除阻断。连接策略的模拟测试验证只尝试一次关闭、最多一次刷新、15／60 秒等待边界以及歧义／取消时不刷新。前端测试执行实际观察器脚本，验证游戏连接识别、多个连接拒绝与监听器去重，并检查按钮状态和不完整历史统计。

可选的 `examples/midgame_smoke.rs` 是独立实机验收工具，会启用自动操作；仅在自行打开免费 AI 对局后运行。它使用生产捕获及恢复路径，把日志写入系统临时目录 `akagi-midgame-acceptance`，三次服务端确认后退出。它不创建对局、不修改用户配置；普通验收优先使用界面。

```sh
cargo run --example midgame_smoke -- 9222 180
```

此工具的退出成功仍需同时人工核对真实局面与点击位置。用户已确认 B 路径可行；该反馈并非本工具的成功运行记录。
