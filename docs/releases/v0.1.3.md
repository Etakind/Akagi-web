# Akagi Web 0.1.3

## Changes since 0.1.2

- Keep the drawn tile visible in suggestions after your riichi, including automatic tsumogiri turns without an action prompt. These display updates do not cause additional discard clicks.
- Continue handling legal ron and tsumo opportunities after riichi. When automatic play is enabled, select the win action instead of suppressing the decision or passing.
- Replace empty `{}` records in `majsoul/autoplay.log` with immediate, structured evidence for click attempts, CDP press/release results, matching client requests and server confirmations. A verified operation requires the complete chain from the same click attempt and action window; retries cannot share evidence.
- Keep the audit log free of accounts, credentials, tiles, coordinates, game UUIDs, raw protocol payloads and arbitrary error text. The log retains schema version 1. Existing empty records cannot be reconstructed.
- Add regressions for three-player/four-player riichi draws and wins, failed clicks, retries, manual input, stale windows, incomplete evidence and privacy. Include the Python log-audit regression in CI.

## Verification and reading the log

Local four-player games provided 22 riichi tsumogiri updates with matching display data and server discards, plus two winning draws. Eight automatic wins (five ron, three tsumo) had complete click/request/server evidence, including four wins after riichi. These are anonymized local observations; three-player coverage is from regression tests. Logs verify display data, not individual rendered screen frames.

The source checkout provides [`scripts/audit_autoplay.py`](https://github.com/Etakind/Akagi-web/blob/v0.1.3/scripts/audit_autoplay.py). Run it with the path to a session's `majsoul/autoplay.log` to count `verified_ron` and `verified_tsumo`. A suggestion, an attempted click or a successful RPC reply alone is insufficient proof of an automatic win. See the [log format](https://github.com/Etakind/Akagi-web/blob/v0.1.3/src/logger/README.md).

# Akagi Web 0.1.3（简体中文）

## 相较于 0.1.2 的更新

- 修复本人立直后建议不再显示摸打牌的问题，包括没有操作提示时的自动摸切。显示更新不会额外点击弃牌。
- 修复立直后荣和、自摸决策被跳过的问题。开启自动打牌时，合法和牌机会会选择和牌操作。
- 修复 `majsoul/autoplay.log` 全部为 `{}` 的问题，逐事件即时记录点击尝试、CDP 按下／释放结果、匹配客户端请求和服务器确认。只有同一次点击、同一操作窗口的完整证据链才会标记为已验证，重试不能混用证据。
- 审计日志排除账号、凭据、牌、坐标、游戏 UUID、原始协议载荷及任意错误文本，继续使用格式版本 1。旧的空记录无法追溯补回。
- 增加三麻／四麻立直摸牌和和牌、点击失败、重试、人工输入、过期窗口、不完整证据及隐私回归，并将 Python 日志审计回归接入 CI。

## 验证范围与日志读取

本机四麻实局确认了 22 次立直后摸打：显示数据与服务器摸打均一致；另有两次摸牌直接和牌。共 8 次自动和牌（5 次荣和、3 次自摸）具有完整的点击／请求／服务器证据，其中 4 次发生在立直后。这里只引用匿名统计；三麻验证来自回归测试。日志确认显示数据，不能逐帧确认屏幕渲染。

源码提供 [`scripts/audit_autoplay.py`](https://github.com/Etakind/Akagi-web/blob/v0.1.3/scripts/audit_autoplay.py)，以会话的 `majsoul/autoplay.log` 路径为参数运行，可统计 `verified_ron` 和 `verified_tsumo`。单独的建议、点击尝试或 RPC 成功回复不能证明自动和牌成功。详见[日志格式说明](https://github.com/Etakind/Akagi-web/blob/v0.1.3/src/logger/README.md)。
