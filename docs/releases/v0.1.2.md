# Akagi Web 0.1.2

## Changes

- Restore Majsoul three-player/four-player state when capture starts mid-game or reconnects. The Capture panel exposes an explicit Recover and continue action with recovery status.
- Rebuild the tracker, bundled model and automatic-action context as one recovery transaction, without generating historical suggestions or automatic input. Resume decisions only on subsequent valid live action windows.
- Bind suggestions and input to the current capture generation and server action window. Superseded connections cannot end the current game or mutate its shared input state.
- Mark incomplete game history as partial and exclude it from complete-match placement and PT statistics. Same-match reconnects retain previously captured complete rounds; old history remains readable.
- Enable the overlay once when upgrading an existing configuration, while preserving later user preferences. Keep the complete Settings action bar visible while scrolling.
- Refresh English and Chinese installation/build guides with platform-specific tooling checks, upstream differences, and security/privacy information.
- Make the browser-approval timeout regression accept Windows connection-reset closure without changing runtime timeout behavior.

## Recovery limits

Recovery is user-triggered and requires a uniquely identified supported official Majsoul page and game connection. It first closes that game connection once and waits up to 15 seconds for client authentication and synchronization. If needed, it reloads the same page at most once and waits up to 60 seconds. Ambiguity, cancellation or failure must not cause repeated disconnects or refreshes.

The operation window inherited from synchronization is skipped because its elapsed-time unit is unverified. Complete that action manually if necessary, then wait for a new live window. Automatic play remains opt-in; the overlay migration does not enable automatic play. Tenhou recovery behavior is unchanged.

Offline replay and regression checks do not establish compatibility with every live client, match phase or click layout. See the [recovery and manual acceptance guide](https://github.com/Etakind/Akagi-web/blob/v0.1.2/docs/MIDGAME_RECOVERY.zh-CN.md). Do not use ranked games to test automation.

## Downloads and safety

ZIPs are provided for Windows x64, macOS Intel/Apple Silicon and Linux x64/ARM64. Linux also provides DEB/RPM packages. Asset inventories and SHA256 checksums accompany each target.

This release is unsigned and not notarized; checksums alone do not establish publisher identity. See the [installation guide](https://github.com/Etakind/Akagi-web/blob/v0.1.2/README.md).

Automatic play may violate game rules or lead to account penalties. Keep CDP on loopback and protect the isolated browser profile. Recovery diagnostics preserve the existing redaction boundary; no raw protocol payloads or credentials are added to logs.

# Akagi Web 0.1.2（简体中文）

## 更新内容

- 支持雀魂三麻／四麻中途启动采集及重连后的局面恢复。采集面板提供主动触发的「恢复并继续」按钮和恢复状态。
- 将 Tracker、内置模型和自动操作上下文作为一次恢复事务重建，不产生历史建议或自动输入；仅在后续有效实时操作窗口恢复决策。
- 建议和输入绑定当前采集代次与服务端操作窗口。已被取代的旧连接不能结束当前对局或改变共享输入状态。
- 不完整历史标注为「中途采集」，不参与完整对局的名次与 PT 统计。同场重连保留已采集的完整小局，旧历史仍可读取。
- 升级已有配置时一次性开启悬浮窗，之后保留用户选择；设置页面滚动时完整操作栏保持可见。
- 更新中英文安装与构建指南，补充各平台工具检查、上游差异及安全／隐私说明。
- 浏览器授权超时回归接受 Windows 的连接重置关闭方式，不改变运行时超时行为。

## 恢复边界

恢复必须由用户主动触发，且需要唯一识别的受支持雀魂官方页面及游戏连接。程序先关闭该游戏连接一次，等待客户端认证与同步最多 15 秒；必要时对同一页面最多刷新一次，再等待最多 60 秒。页面／连接歧义、取消或失败不能造成反复断线或刷新。

同步中遗留的操作窗口会跳过，因为其已等待时间单位尚未验证。必要时手动完成当前行动，再等待新的实时窗口。自动打牌仍需主动开启，悬浮窗迁移不会开启自动打牌；天凤恢复行为不变。

离线回放与回归检查不代表所有实机客户端、对局阶段或点击布局均已验证。详见[恢复与手动验收指南](https://github.com/Etakind/Akagi-web/blob/v0.1.2/docs/MIDGAME_RECOVERY.zh-CN.md)。不要在段位场测试自动操作。

## 下载与安全

提供 Windows x64、macOS Intel／Apple Silicon、Linux x64／ARM64 ZIP；Linux 另提供 DEB／RPM。各目标附资产清单与 SHA256。

本版本未签名、未公证，摘要本身不能证明发布者身份。详见[安装与运行指南](https://github.com/Etakind/Akagi-web/blob/v0.1.2/README.zh-CN.md)。

自动打牌可能违反游戏规则并导致账号处罚。CDP 仅使用回环地址，请保护隔离浏览器目录。恢复诊断沿用既有脱敏边界，不新增原始协议载荷或凭据日志。
